# 剑盾乱数统合脚本

入口是 **`剑盾乱数统合.ecs`**：一个完整脚本，不需要导入其余九份文件。桌面的脚本库默认载入它；也可以通过「打开」载入放在其他目录的副本。

按当前 Native EasyCon 执行器的语法重写：显式 `WAIT`、有名局部变量、带类型的 `FUNC / CALL / RETURN`、明确的比较运算、限次搜图循环。共用唤醒、128位测种、日期调整、返回游戏和日期菜单恢复函数。光速与原地过帧原作者为「未来的未来」，原稿署名保留。

## 选择功能

在界面的「功能」下拉框选择；直接编辑文件时修改顶部 `_功能`，其余参数也集中在文件顶部。默认 `0` 只打印说明，可以在未连接设备时运行。

| 编号 | 功能 | 主要参数与起点 |
| --- | --- | --- |
| 1 | 测种 | 对应原「测种」，菜单光标按旧脚本放置；使用 `_测种判定` |
| 2 | 启动后测种 | 对应原「剑盾测种」，保留启动等待及菜单右移入口 |
| 3 | 卡对战 bug | 从游戏画面进入 Y-Comm，联网及匹配成功后执行原 HOME 操作 |
| 4 | 光速过帧 | `_过帧数`、光速延迟与判定间隔；先完成旧脚本要求的时间 bug 准备 |
| 5 | 原地过帧 | `_过帧数`、原地移动／上移延迟；同样先准备时间 bug |
| 6 | 自行车 | `_自行车次数`、同步日期、普通天气日期；实际执行 `次数×5−2` 组上下车 |
| 7 | 雷雨自行车 | `_自行车次数`、同步／雷雨／普通天气日期；结束露营后执行 `次数×5` 组上下车 |
| 8 | 精准过帧 | 从旧脚本的动画能力页开始；`_过帧数`、预留、天气误差、撞帧方向、保存开关 |
| 9 | 迷人身躯换位 | 队伍页面沿用旧脚本光标起点（第2格）；`_迷人身躯` 为目标队伍位置1～6，目标已在第1格时不交换 |

测种、计算目标、推进、精确定位之间需要核对种子与画面，因此每次只运行所选阶段。**不会把九份脚本从头到尾连续执行。**

`_推进后测种` 控制功能4～7：`1` 在推进后追加128次动画并输出测种序列，`0` 停在能力页。追加测种会继续消耗乱数；推进数不包含这128次，之后应使用新测种结果重新定位。原地过帧在统合版也支持此选项。

`_过帧数`、`_自行车次数` 默认0，选择需要它们的功能后必须填写正数。光速／原地沿用原脚本“初始化操作算1次、循环执行数量减1”的约定，实际消耗仍需实机校准。普通自行车原判定阈值85，其余测种原阈值80，统合参数默认80，可按模板调整。

同步日期必须是运行时真正同步到的日期；当前月／日指普通天气日期。日期算法沿用 Switch 日期选择器的月／日差，未处理未知年份、无效日期或跨月自动修正，运行前应核对。

## 标签、超时和中止

标签仍由用户补充，名称保持不变。在「选择 ImgLabel 目录」指定模板目录，或者放在脚本同目录。桌面只检查当前功能可能用到的标签：

| 功能 | 标签 |
| --- | --- |
| 0、8、9 | 无 |
| 1、2、6 | YY、铁甲物理 |
| 3 | YY、联网、匹配中、匹配成功 |
| 4、5 | YY、同步时间、时区、时区2、现在的日期与时间、铁甲物理 |
| 7 | YY、结束露营、铁甲物理 |

功能4～7关闭追加测种后不要求「铁甲物理」。标签检查根据不可变参数和函数调用关系分析；编辑后出现的动态条件仍会保留两条路径的依赖。缺少模板或采集画面时不会开始发送脚本按键。

`_识别次数上限` 默认120，是每个搜图等待的**尝试次数**，不是精确秒数；等待时间还包含按键和菜单恢复时长。超过次数返回中止状态，界面明确显示“未完成”，不会继续后面的阶段。停止或异常也会释放按键。

重写中修复了负日期差循环、雷雨日期恢复方向、过帧1次／批次边界和恢复计数器覆盖延迟的问题。九个入口、128位输出、超时中止、缺失标签、日期正反方向、换位和参数联动已使用模拟设备检查；尚未用真实 Switch、采集卡和用户标签验证菜单时序或命中率。

## 旧单项适配记录

这 9 份脚本由用户提供。`originals/` 按字节保留原始 `.txt`，同名 `.ecs` 是此前的单项适配版，仅保留对照；默认脚本库使用上面的统合版。以下说明描述旧单项适配版。

## 使用

在「伊机控 → 脚本库 / 执行」载入脚本，填写左侧参数，然后点击「检查脚本」。
`填入这里` 是必填占位符，不是 ECS 表达式；不会自动代入测试值。
修改后的脚本可另存为 `.ecs`，参数值会写入保存副本。

搜图模板尚未随脚本提供。补齐后选择原伊机控 `ImgLabel` 目录（或其上级目录），也可以把它放在脚本同目录。
点击「共通设置 → 保存」会同时保存所选模板目录。运行前检查缺失模板和采集画面，缺少依赖时不执行脚本按键。

## 适配改动

- 全部裸数字等待改为显式 `WAIT`，保留原按键顺序和时长。
- 原地过帧：初始化累计计数器 `$5`；处理只过一次和整 60 次批次的退出边界；恢复菜单使用独立 `$12` 计数，避免覆盖 `$1` 的摇杆延迟。
- 精准过帧：先把负的日期差取正，再进入 `FOR`，修复负次数直接跳过操作。界面校验扣除预留帧和天气误差后的帧数。
- 雷雨自行车：日期同步后直接以同步月 / 日计算差值，修复差值为负时把当前位置越算越远的问题。
- 卡对战 bug：纯搜图等待循环增加 100 毫秒间隔。
- 5 份包含测种的脚本用字符串累计结果，结束后一次输出 128 位序列，避免旧版 `PRINT ... & \` 的续行差异。

## 验证范围

自动化测试使用模拟手柄、模拟标签结果和跳过真实等待的执行器。
覆盖 9 份脚本正常结束、128 位测种输出、原地过帧 1 / 2 / 61 / 62 / 121 次、恢复后的延迟保持和负日期差循环。
这些检查验证解析、分支和计数，不验证 Switch 菜单位置、联机时机、真实帧数、天气或图像匹配效果。
原脚本的菜单前提、日期推进规则、识别阈值与设备延迟仍需补齐标签后实机校准。
